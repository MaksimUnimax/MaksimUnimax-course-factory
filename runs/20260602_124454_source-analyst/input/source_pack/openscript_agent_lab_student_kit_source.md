# OpenScript Agent Lab Student Kit — source document for Course Factory first run

## Назначение документа

Этот документ является исходным материалом для первого тестового запуска Course Factory.

Он описывает учебную модель, где ученик без опыта программирования учится управлять AI-разработкой через связку:

- ChatGPT;
- Codex;
- сервер;
- GitHub;
- проверка результата;
- документация как источник правды.

Этот документ не является готовым курсом. Он является source material, который первый агент должен разобрать и превратить в `source_digest.md`.

## Целевая учебная идея

Курс должен показать новичку, что AI-разработка может быть управляемым процессом.

Главная мысль:

> Ученик не должен сам писать код. Ученик должен понимать цель шага, давать ChatGPT исходные материалы и ограничения, запускать Codex на одну конкретную задачу, проверять результат и двигаться дальше только после подтверждения.

## Базовая схема работы

Учебная связка выглядит так:

1. Ученик загружает исходные материалы и выбирает настройки курса.
2. ChatGPT объясняет следующий шаг простым русским языком.
3. ChatGPT готовит точное задание для Codex.
4. Codex выполняет одну ограниченную задачу в серверном проекте.
5. Codex печатает отчёт с результатом.
6. ChatGPT проверяет отчёт и public GitHub.
7. Ученик смотрит результат в интерфейсе или репозитории.
8. Только после проверки команда переходит к следующему шагу.

## Правило одного шага

Одна задача должна решать одну проблему.

Нельзя смешивать:

- создание проекта;
- настройку GitHub;
- добавление UI;
- запуск агента;
- исправление ошибок;
- обновление документации;
- работу с секретами.

Если несколько задач смешаны, становится невозможно понять, что именно сломалось.

## Правило проверки перед изменением

Перед изменением нужно сначала доказать текущее состояние.

Пример правильного порядка:

1. Проверить, какие файлы существуют.
2. Проверить Git status.
3. Проверить текущий endpoint или страницу.
4. Найти точную причину проблемы.
5. Сделать минимальное изменение.
6. Повторно проверить результат.
7. Только потом commit и push.

## GitHub как история проекта

GitHub нужен не как украшение, а как источник истории.

Ученик должен понимать:

- commit фиксирует состояние проекта;
- push отправляет изменения в публичный репозиторий;
- public GitHub позволяет проверить, что работа действительно сохранена;
- если изменения не запушены, их нельзя считать завершёнными;
- если в commit попали лишние файлы, задача считается выполненной неправильно.

## Документация как источник правды

В проекте должны быть документы, которые объясняют:

- что это за проект;
- какие правила работы действуют;
- какой текущий этап;
- какие решения уже приняты;
- какие вопросы ещё открыты;
- какие артефакты создают агенты;
- что можно считать готовым результатом.

Документация должна обновляться после важных изменений, но нельзя превращать один run в смесь кода, документации и несвязанных правок.

## Сервер и публичный адрес

Если ученик смотрит результат в браузере, ChatGPT не должен давать адрес `localhost`.

`localhost` означает компьютер или сервер, где запущен процесс. Для ученика это часто неправильный адрес.

Если проект открыт на сервере, ученику нужно показывать публичный IP или домен.

Пример правильной проверки:

- сервис слушает нужный порт;
- локальная проверка на сервере проходит;
- публичная проверка снаружи проходит;
- страница открывается в браузере ученика.

## Секреты и ключи

Нельзя печатать или сохранять в публичный репозиторий:

- private SSH key;
- пароли;
- API keys;
- tokens;
- `.env`;
- runtime auth files;
- приватные deploy keys.

Публичную часть SSH key можно показывать только если она предназначена для добавления в GitHub.

Приватную часть ключа нельзя выводить в чат, отчёт или commit.

## Первый учебный проект

Первый учебный проект может быть небольшой “фермой агентов” или упрощённым agent workflow.

Главная цель первого проекта — не построить production-систему, а научить ученика процессу:

- создать структуру проекта;
- завести документы;
- сделать один безопасный запуск;
- проверить результат;
- сохранить изменения в Git;
- понять разницу между агентом и инструментом.

## Агент и инструмент

Агент — это исполнитель с ролью и инструкциями.

Инструмент — это функция или действие, которое агент может использовать.

Пример:

- агент: “финансовый помощник”;
- инструмент: “добавить расход”.

Нельзя смешивать агента и инструмент в одно понятие.

## Course Factory pipeline

Course Factory должен работать как цепочка артефактов.

Пользователь один раз загружает исходные документы и выбирает настройки курса.

Дальше агенты работают по цепочке:

1. Source Analyst читает исходники и создаёт `source_digest.md`.
2. Course Architect берёт `source_digest.md` и “Задание на курс”, затем создаёт `curriculum_map.md`.
3. Lesson Designer берёт `curriculum_map.md` и создаёт план конкретного урока.
4. Lesson Writer пишет текст урока по плану.
5. Assessment Designer готовит проверку знаний.
6. Quality Reviewer проверяет качество.
7. Grounding Reviewer проверяет, что факты не выдуманы.
8. Publisher готовит итоговую выдачу.

Следующий агент не должен требовать новый архив от ChatGPT, если нужные данные уже были загружены или созданы предыдущим агентом.

## Что должен сделать Source Analyst

Первый агент не пишет курс.

Он должен разобрать этот документ и выделить:

- список источников;
- основные темы;
- ключевые процедуры;
- важные термины;
- подсказки о целевой аудитории;
- ограничения безопасности;
- противоречия;
- недостающую информацию;
- полезные факты из источника;
- аккуратные учебные выводы;
- решения, которые должен принять человек.

Результат первого агента должен быть `source_digest.md`.

## Что нельзя делать Source Analyst

Source Analyst не должен:

- писать уроки;
- строить карту курса;
- делать тесты;
- придумывать недостающие факты;
- скрывать gaps;
- превращать документ в рекламный текст;
- запускать следующих агентов.

## Ожидаемый учебный стиль

Курс должен быть на русском языке.

Стиль:

- простой;
- спокойный;
- пошаговый;
- без перегруза терминами;
- с короткими объяснениями;
- с постоянной проверкой результата.

Если термин нужен, его нужно объяснить простыми словами.

## Риски для курса

Основные риски:

- ученик не понимает Git и путает commit/push;
- ученик не понимает разницу ChatGPT и Codex;
- ученик начинает запускать много задач сразу;
- в публичный repo могут попасть секреты;
- `localhost` может быть показан как адрес для ученика;
- downstream agents могут попросить повторно загрузить файлы вместо использования предыдущих артефактов;
- агент может начать писать курс раньше, чем сделан разбор источников.

## Недостающая информация

Для полноценного курса могут понадобиться дополнительные материалы:

- полный пример AGENTS.md;
- шаблоны Codex prompt;
- пример хорошего Codex report;
- пример плохого Codex report;
- пример проверки public GitHub commit;
- пример безопасного deploy key workflow;
- карта модулей учебного проекта;
- критерии готовности каждого этапа.

Если этих материалов нет, их нужно отметить как gaps, а не выдумывать.

## Human decisions

Человек должен решить:

- какой точный размер курса делать первым;
- насколько подробно объяснять Git и сервер;
- нужен ли отдельный урок про безопасность секретов;
- делать ли первый проект “фермой агентов” или более простым workflow;
- какие артефакты считать обязательными для перехода к следующему агенту.

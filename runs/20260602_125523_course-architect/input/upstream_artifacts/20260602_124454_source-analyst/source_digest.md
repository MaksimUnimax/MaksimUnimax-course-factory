## 2. Main topics

- AI-разработка как управляемый процесс, а не как хаотичный набор действий.
- Связка ChatGPT -> Codex -> сервер -> GitHub -> проверка результата -> документация.
- Правило одного шага: одна задача решает одну проблему.
- Проверка состояния перед изменением: сначала доказать текущее состояние, потом менять.
- GitHub как история проекта: commit, push, public verification.
- Документация как источник правды.
- Различие между `localhost` и публичным адресом сервера.
- Безопасность: секреты, ключи, токены, `.env`, runtime auth files.
- Первый учебный проект как упрощённый agent workflow.
- Роли агентов в Course Factory: Source Analyst, Course Architect и следующие агенты по цепочке.

## 3. Key procedures

- Пользователь один раз загружает исходные материалы и выбирает настройки курса.
- ChatGPT объясняет следующий шаг простым русским языком.
- ChatGPT подготавливает точное задание для Codex.
- Codex выполняет одну ограниченную задачу.
- Codex оставляет отчёт с результатом.
- ChatGPT проверяет отчёт и public GitHub.
- Ученик видит результат в интерфейсе или репозитории.
- Только после проверки переходят к следующему шагу.
- Перед изменением нужно проверить файлы, `git status`, endpoint или страницу, затем сделать минимальное изменение и повторно проверить результат.

## 5. Target audience clues

- В документе явно сказано, что курс рассчитан на новичка без опыта программирования.
- Курс должен объяснять управление AI-разработкой простым русским языком.
- Ученик должен уметь понимать цель шага, запускать Codex на одну задачу и проверять результат.
- Важны пошаговые объяснения, короткие формулировки и постоянная проверка результата.
- Документ подсказывает, что аудитория может путать `commit` и `push`, `ChatGPT` и `Codex`, а также `localhost` и публичный адрес.

## 6. Safety constraints

- Нельзя печатать или сохранять private SSH keys, пароли, API keys, tokens, `.env`, runtime auth files и private deploy keys.
- Нельзя смешивать несколько задач в один запуск, если это мешает понять причину сбоя.
- Нельзя показывать `localhost` ученику как публичный адрес.
- Нельзя запускать следующие агенты, пока не сделан разбор источников.
- Нельзя превращать документ в рекламный текст или выдавать предположение за факт источника.
- Нельзя использовать секреты или закрытые материалы без отдельного разрешения.

## 10. Usable source facts

- Первый тестовый проект строится вокруг управляемого agent workflow.
- Ученик должен загружать исходники и выбирать настройки курса один раз на старте.
- Source Analyst должен разобрать исходники, а не писать курс.
- Course Architect должен работать поверх `source_digest.md` и course brief.
- Одна задача должна решать одну проблему.
- Перед изменением нужно сначала доказать текущее состояние.
- GitHub нужен как история проекта, а не как декоративный элемент.
- Документация должна объяснять правила, этапы, решения и открытые вопросы.
- Серверная проверка должна включать локальную и публичную проверку.
- Секреты нельзя печатать или коммитить.

## 11. Instructional inferences

- Курс для этого материала должен быть коротким, практическим и поэтапным.
- В первом курсе полезно явно учить проверке состояния до изменения, чтобы сформировать безопасную привычку.
- Для новичка полезно отдельно объяснить разницу между `commit` и `push`, а также между локальным и публичным адресом.
- Для курса по этому материалу полезно сделать акцент на управляемом запуске одного агента, а не на массовой автоматизации.
- Поскольку документ строится вокруг проверки результата, downstream курс должен включать явные проверки после каждого шага.
- Русский простой стиль и короткие объяснения следует считать методическим требованием, а не украшением.

# Исходный документ для Course Factory: OpenScript Agent Lab Student Kit

## 1. Назначение исходника

Этот документ является единым исходным материалом для первого тестового запуска агента `Source Analyst` в Course Factory.

Задача агента — не писать курс и не проектировать уроки, а разобрать этот документ как исходник и создать результат:

`output/source_digest.md`

Документ собран по публичному репозиторию:

`https://github.com/MaksimUnimax/openscript-agent-lab-student-kit`

## 2. Что такое OpenScript Agent Lab Student Kit

`OpenScript Agent Lab Student Kit` — это публичный учебный комплект OpenScript Agent Lab.

Это не рабочий проект ученика и не место разработки.

Его роль:

- хранить стартовые документы;
- хранить правила работы ChatGPT и Codex;
- хранить шаблоны prompt’ов;
- хранить roadmap первого проекта;
- хранить заготовку структуры будущего проекта ученика;
- служить безопасным публичным источником материалов.

Рабочий проект ученика создаётся отдельно:

- на сервере ученика;
- в отдельной папке проекта;
- в отдельном git-репозитории ученика;
- с отдельной историей commit/push.

Student Kit нельзя редактировать или пушить в рамках работы ученика.

Из Student Kit можно только брать стартовые материалы.

## 3. Главная учебная идея

Курс не должен учить классическому программированию.

Курс должен научить человека работать в связке:

`ученик → ChatGPT → Codex → сервер → GitHub → проверка результата`

Ученик может быть абсолютным новичком:

- не программист;
- не знает, что такое сервер;
- не знает, что такое git;
- не знает, что такое терминал;
- не знает, что такое SSH;
- не знает, что такое API;
- не понимает английские технические слова;
- может бояться длинных технических объяснений.

Поэтому обучение должно идти простым русским языком, маленькими шагами и через реальные действия.

## 4. Роли в учебном процессе

### Ученик

Ученик:

- описывает цель обычными словами;
- копирует готовые prompt’ы в Codex;
- присылает отчёты Codex обратно в ChatGPT;
- проверяет видимый результат;
- подтверждает, что шаг понятен и принят.

### ChatGPT-наставник

ChatGPT:

- объясняет, что сейчас делаем;
- объясняет, зачем это нужно;
- проектирует следующий маленький шаг;
- пишет полный prompt для Codex;
- проверяет отчёты Codex;
- объясняет результат ученику;
- не соглашается автоматически с неправильными предложениями;
- не даёт много шагов сразу;
- не использует localhost как адрес для ученика;
- не отправляет ученика самостоятельно разбираться в логах.

### Codex

Codex:

- технический исполнитель;
- работает на сервере;
- выполняет один конкретный prompt;
- меняет только разрешённые файлы;
- проверяет результат;
- делает commit/push, если это входит в задачу;
- возвращает отчёт между `CHATGPT_REPORT_BEGIN` и `CHATGPT_REPORT_END`.

Codex не должен сам выбирать архитектуру вместо ChatGPT и ученика.

## 5. Главный цикл работы

Основной цикл обучения:

1. Ученик описывает задачу обычными словами.
2. ChatGPT превращает её в один понятный технический шаг.
3. ChatGPT даёт полный prompt для Codex.
4. Ученик копирует prompt в Codex.
5. Codex работает на сервере.
6. Codex возвращает отчёт.
7. Ученик присылает отчёт ChatGPT.
8. ChatGPT проверяет отчёт.
9. ChatGPT объясняет, что получилось.
10. ChatGPT даёт следующий маленький шаг.

Ученик должен научиться именно этому циклу.

## 6. Первый учебный проект

Первый учебный проект называется:

`Ферма агентов с финансовым инструментом`

Это рабочий проект, а не симулятор.

В результате у ученика должны появиться:

- серверная папка проекта;
- git-репозиторий проекта;
- документация проекта;
- визуальный просмотр структуры проекта;
- первый агент;
- возможность добавлять агентов;
- финансовый инструмент;
- запись расходов в базу;
- обработка текстового расхода;
- обработка фото чека;
- обработка голосового сообщения;
- сохранение результата в базе данных;
- понимание, как дальше работать через ChatGPT + Codex + сервер + GitHub.

Финансовый инструмент используется как первый практический пример инструмента.

Важно различать:

- агент отвечает человеку;
- инструмент выполняет действие;
- агент не должен напрямую писать в базу;
- финансовую работу делает финансовый инструмент;
- база данных хранит результат.

## 7. Рабочий режим

Отдельную учебную имитацию проекта делать нельзя.

Ученик работает в реальном режиме:

- на своём сервере;
- со своим проектом;
- с реальными файлами;
- с реальным git;
- с реальным Codex;
- с реальными проверками;
- с реальным результатом.

Но ChatGPT должен вести ученика маленькими шагами и не перегружать.

## 8. Правило одного шага

Один шаг — одна задача.

Нельзя смешивать в одном шаге:

- создание сервера;
- настройку git;
- Telegram;
- голос;
- фото чека;
- базу данных;
- дизайн интерфейса;
- обновление документации;
- деплой;
- создание нового инструмента;
- проверку старой ошибки.

Правильный порядок:

1. проверить текущее состояние;
2. понять, что именно нужно сделать;
3. сделать один маленький шаг;
4. проверить результат;
5. только потом идти дальше.

Если задача большая, ChatGPT обязан разделить её.

## 9. Правило “сначала проверка”

Перед изменением проекта нужно проверять текущее состояние.

Смысл для ученика:

> Перед изменениями мы сначала смотрим, в каком состоянии проект. Это как сфотографировать комнату перед ремонтом, чтобы потом понимать, что изменилось.

Нельзя чинить вслепую.

Если не хватает фактов, ChatGPT должен дать Codex проверочный prompt, а не угадывать.

## 10. Git и GitHub

Git объясняется ученику простыми словами:

`Git — это история проекта.`

Git нужен, чтобы:

- сохранять состояние проекта;
- понимать, какие изменения были сделаны;
- возвращаться назад, если что-то сломалось;
- видеть, что Codex реально изменил;
- хранить документацию рядом с проектом.

GitHub нужен как публичная или удалённая копия проекта и как точка связи между ChatGPT, Codex и документацией.

Для начала работы ученик должен:

1. иметь GitHub-аккаунт;
2. создать личный публичный репозиторий проекта;
3. не добавлять README;
4. не добавлять `.gitignore`;
5. не добавлять License;
6. прислать ссылку ChatGPT;
7. подтвердить, что repo Public.

Без этого ChatGPT не должен давать первый Codex prompt.

## 11. Deploy key

Для записи на GitHub с сервера используется SSH deploy key.

Правило:

- Codex создаёт отдельный ключ для конкретного repo.
- Codex печатает только публичную часть ключа.
- Приватный ключ нельзя печатать, копировать, отправлять в ChatGPT или вставлять в GitHub.
- В GitHub добавляется только строка, начинающаяся примерно с `ssh-ed25519`.
- В deploy key нужно включить `Allow write access`.
- После этого Codex проверяет push.

Этот процесс нужно объяснять ученику простым языком:

> Сейчас мы дадим серверу право записывать файлы в GitHub-репозиторий. Для этого Codex создаст специальный ключ. В GitHub нужно вставить только публичную часть ключа.

## 12. Документация как источник правды

Проект нельзя вести по памяти, если есть документация.

Документация нужна, чтобы:

- ChatGPT понимал текущий план;
- Codex понимал, что делать;
- ученик мог продолжить в новом диалоге;
- проект не терял контекст;
- ошибки и решения сохранялись.

Если документации нет, нельзя начинать разработку. Сначала нужно создать или загрузить документацию.

Документы должны копироваться из публичного Student Kit в личный проект ученика.

Student Kit — это источник материалов, а не рабочий repo.

## 14. Стартовый порядок работы ученика

Стартовый порядок:

1. Ученик загружает в ChatGPT два документа:
   - `01_ИНСТРУКЦИЯ_ДЛЯ_CHATGPT.md`
   - `02_СТАРТ_ПРОЕКТА_GIT_ДОКУМЕНТАЦИЯ_СТРУКТУРА.md`

2. ChatGPT проверяет, что понял режим:
   - ученик нулевой;
   - объяснять просто;
   - один шаг за раз;
   - Codex работает на сервере;
   - не давать localhost.

3. ChatGPT приветствует ученика и объясняет, что первый этап — GitHub и git.

4. ChatGPT спрашивает, есть ли GitHub-аккаунт.

5. Если аккаунта нет — ChatGPT даёт инструкцию по созданию GitHub-аккаунта.

6. Если аккаунт есть — ChatGPT даёт инструкцию по созданию личного публичного repo.

7. Ученик присылает ссылку на repo.

8. ChatGPT проверяет, что repo Public.

9. Только после этого ChatGPT даёт первый Codex prompt.

10. Codex создаёт/проверяет project root на сервере.

11. Codex создаёт git в проекте ученика.

12. Codex копирует стартовые документы в рабочий проект ученика.

13. Codex делает первый commit.

14. Codex настраивает push в личный GitHub ученика.

15. ChatGPT генерирует zip расширения для браузера.

16. Ученик устанавливает расширение.

17. Ученик подтверждает, что prefix вставляется.

18. Codex поднимает страницу структуры проекта.

19. Ученик проверяет страницу по публичному IP своего сервера.

20. После подтверждения можно переходить к roadmap.

## 15. Расширение ChatGPT

Расширение нужно не как учебник для ученика.

Оно нужно, чтобы ChatGPT не забывал правила учебного режима.

Расширение напоминает:

- ученик абсолютный новичок;
- объяснять простым русским языком;
- один шаг за раз;
- если нужен Codex — давать полный prompt;
- если пришёл отчёт Codex — сначала проверять отчёт;
- не давать localhost как адрес ученику;
- не путать тестовый IP с IP ученика;
- агент считается рабочим только через правильный runtime;
- fake/template reply не считается успехом;
- Telegram — канал общения, а не бизнес-инструмент;
- документацию нужно обновлять после важных этапов.

До подтверждения ученика, что расширение установлено и prefix вставляется, нельзя переходить к каркасу проекта.

## 16. Адреса и запрет localhost

ChatGPT не должен давать ученику адреса:

- `localhost`;
- `127.0.0.1`;
- адрес локального компьютера;
- адрес тестового сервера другого человека.

Если проект работает на сервере, ученику можно давать только:

- публичный IP его сервера;
- порт на публичном IP его сервера;
- домен ученика, если он настроен.

Если публичный адрес не доказан, ChatGPT должен остановиться и сказать:

> Я не могу дать адрес для открытия в браузере, пока Codex не подтвердит публичный IP или домен твоего сервера.

## 17. Визуальный просмотр структуры проекта

В учебном маршруте должна быть ранняя визуальная проверка:

`Структура проекта на сервере`

Это отдельная read-only страница, а не основной интерфейс Agent Lab.

Назначение:

- показать ученику, что проект реально создан на сервере;
- показать папки и файлы;
- дать возможность раскрывать папки;
- не давать редактировать;
- не давать скачивать;
- не показывать содержимое файлов;
- не показывать секретные имена.

Ученик должен открыть страницу по публичному IP своего сервера и проверить:

- страница открылась;
- виден заголовок;
- видны папки;
- видны файлы;
- папки раскрываются;
- файлы не открываются для редактирования;
- нет ошибки;
- адрес не `localhost`.

## 18. Основной roadmap первого проекта

Roadmap ведёт ученика через создание рабочего проекта.

Главная цель — не просто получить готовый код, а научиться работать в связке:

`ученик → ChatGPT → Codex → сервер → GitHub → проверка результата`

Примерная длительность:

- 50–70 технических шагов Codex;
- 40–70 часов общей работы;
- быстрее, если всё идёт без ошибок;
- дольше, если ученик часто задаёт вопросы или появляются технические проблемы.

Основные этапы:

1. Старт: сервер, GitHub, git, документы.
2. Визуальная структура проекта.
3. Архитектурный каркас.
4. Hermes/runtime foundation.
5. Agent package foundation.
6. UI фабрики агентов.
7. Первый агент и Telegram.
8. Tool registry.
9. Финансовый инструмент.
10. Чек, голос, второй агент, финальная проверка.

Этапы нельзя перескакивать без причины.

Если ученик просит сразу перейти к голосу, Telegram, фото чека или базе, ChatGPT должен объяснить, почему сначала нужен каркас и проверка простого пути.

## 19. Первый этап roadmap

Первый этап:

1. загрузить два стартовых документа;
2. проверить доступ к серверу;
3. создать папку проекта;
4. создать git;
5. подключить общий публичный docs repo;
6. разложить стартовую документацию;
7. сделать первый commit;
8. подключить GitHub remote;
9. настроить deploy key;
10. проверить push;
11. установить расширение ChatGPT;
12. поднять страницу структуры проекта;
13. проверить страницу по публичному IP;
14. перейти к roadmap.

## 20. Prompt templates

Папка `prompts/` содержит шаблоны prompt’ов для ChatGPT.

Шаблоны не являются готовыми задачами.

ChatGPT должен заполнить:

- RUN_ID;
- RUN_MODE;
- цель;
- scope;
- forbidden scope;
- нужные документы;
- checks;
- acceptance;
- формат отчёта.

Каждый prompt должен начинаться с требования следовать `AGENTS.md`.

Если `AGENTS.md` отсутствует в корне рабочего проекта, Codex должен вернуть STOP.

Типы шаблонов:

- `proof_prompt_template.md` — проверка фактов без изменений;
- `fix_prompt_template.md` — одно минимальное исправление;
- `docs_update_prompt_template.md` — обновление явно указанных документов;
- `codex_report_contract.md` — общий формат отчёта Codex.

## 21. Codex report

Codex должен возвращать отчёт между маркерами:

```text
CHATGPT_REPORT_BEGIN
...
CHATGPT_REPORT_END
```

ChatGPT обязан проверять:

- SUCCESS, STOP или FAIL;
- что изменилось;
- какие файлы изменились;
- какие проверки прошли;
- был ли commit;
- был ли push;
- нет ли секретов;
- нет ли лишних изменений;
- не дал ли Codex localhost как адрес ученику;
- не смешал ли Codex несколько задач.

STOP не считается провалом. STOP означает, что Codex не стал гадать.

FAIL требует отдельной диагностики или минимального исправления.

SUCCESS принимается только после проверки отчёта и ручной проверки результата, если она нужна.

## 22. Правила безопасности и качества

Запрещено:

- соглашаться автоматически;
- давать много шагов сразу;
- говорить сложным языком без необходимости;
- использовать localhost как адрес для ученика;
- подставлять IP тестового сервера в методичку;
- отправлять ученика разбираться самому;
- просить ученика вручную редактировать код;
- смешивать несколько задач в один шаг;
- чинить всё сразу;
- придумывать архитектуру, если она уже есть в документах;
- игнорировать отчёт Codex;
- пропускать проверку результата;
- делать вид, что всё готово, если нет ручной проверки.

## 23. Что считать финалом первого проекта

Финал первого проекта:

- проект живёт на сервере;
- проект сохранён в git;
- есть документация;
- есть визуальный просмотр структуры проекта;
- есть минимум один агент;
- можно добавить второго агента;
- есть финансовый инструмент;
- текстовый расход записывается в базу;
- фото чека обрабатывается;
- голос распознаётся;
- результат попадает в тот же путь, что обычный текст;
- данные сохраняются в базе;
- ученик понимает цикл работы ChatGPT + Codex.

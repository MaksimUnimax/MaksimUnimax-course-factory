# Source digest

`source_digest.md` здесь означает «разбор исходных материалов».

## 1. Source inventory

- Название: OpenScript Agent Lab Student Kit source document
- Путь или идентификатор: `runs/20260601_102242_source-analyst/input/source_pack/openscript_agent_lab_student_kit_source.md`
- Тип источника: markdown-документ, единый source pack для первого тестового запуска Source Analyst
- Краткое назначение: описывает учебную модель работы ChatGPT + Codex + сервер + GitHub, стартовый порядок работы, правила, структуру Student Kit и первый учебный проект
- Можно ли использовать источник для курса: да, как исходный публичный материал для курса про управление ИИ-разработкой и работу по одному шагу за раз

## 2. Main topics

- Учебная связка `ученик → ChatGPT → Codex → сервер → GitHub → проверка результата`
- Простое русскоязычное сопровождение для абсолютного новичка
- Правило одного шага и правило сначала проверки
- Git, GitHub и SSH deploy key как базовые механизмы работы
- Документация как источник правды
- Первый учебный проект: «Ферма агентов с финансовым инструментом»
- Запрет `localhost` для адресов, которые показывает ChatGPT ученику
- Визуальная read-only проверка структуры проекта на сервере
- Prompt templates и формат отчёта Codex
- Разделение агента и инструмента

## 3. Key procedures

- Сначала загрузить в ChatGPT стартовые документы Student Kit
- Проверить, что ученик понимает режим работы и что объяснения должны быть простыми
- Сначала проверить наличие GitHub-аккаунта и публичного repo
- После подтверждения публичного repo дать первый Codex prompt
- Создать на сервере проект, git-репозиторий, документацию и первый commit
- Настроить SSH deploy key и проверить push
- Установить браузерное расширение ChatGPT и убедиться, что prefix вставляется
- Поднять read-only страницу структуры проекта и проверить её по публичному IP
- Затем перейти к roadmap и дальнейшим шагам

## 5. Target audience clues

- Ученик может быть абсолютным новичком
- Ученик может не знать сервер, git, терминал, SSH и API
- Ученик может не быть программистом
- Обучение должно идти маленькими шагами
- Нужен простой русский язык без перегрузки
- Нужно регулярно проверять результат, а не действовать вслепую

## 6. Safety constraints

- Student Kit нельзя редактировать или пушить в рамках работы ученика
- Нельзя использовать `localhost` как адрес для ученика
- Нельзя смешивать много задач в одном шаге
- Нельзя гадать, если фактов не хватает
- Нельзя начинать разработку без документации
- Нельзя печатать приватную часть SSH-ключа
- Нельзя выдавать тестовый адрес другого сервера за адрес ученика
- Нельзя начинать без публичного GitHub repo, если это требуется стартовым порядком

## 10. Usable source facts

- Source Analyst должен создавать `source_digest.md`, а не курс
- Первый учебный проект строится вокруг ChatGPT, Codex, сервера и GitHub
- Для первого шага требуется публичный GitHub repo
- Используется SSH deploy key с включённым write access
- Документация обязана сохраняться и обновляться
- Student Kit — источник материалов, а не рабочий репозиторий ученика
- Первый проект должен идти по одному шагу с промежуточными проверками
- Агент и инструмент — разные сущности
- Visual preview структуры проекта нужен рано и должен быть read-only

## 11. Instructional inferences

- Курс можно строить как курс про управление ИИ-разработкой, а не только про классическое программирование
- Для новичка нужен staged workflow: сначала доступы и документы, потом структура, потом первые изменения
- Для надежной работы нужен строгий `proof → change → verify` цикл
- Коммуникация должна быть короткой, пошаговой и без лишней терминологии
- Каждый крупный этап полезно закреплять отдельным отчетом Codex
